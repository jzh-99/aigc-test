# AIGC 创作用户手册重构设计

## 目标

将 `/docs` 整体重构为面向普通 AIGC 创作用户的任务型使用手册。新手册只解释创作相关功能，帮助用户理解“从哪里开始、如何生成、如何保存复用、如何进入专项工作室完成更长链路创作”。

本次不写团队、后台管理、设置、充值、权限配置等管理类内容。登录页只保留低调手册入口，不把账户管理作为手册主体。

## 当前问题

现有 docs 内容来自旧版产品结构，主要问题：

- 仍按“登录与账户、工作台、图片生成、视频生成、资产库、AI 助手、旧案例”组织，和当前首页、侧边栏、Toby Studio、灵动画布等入口不匹配。
- 页面变化较大，旧截图和旧案例会误导用户。
- 本地 dev server 中 `docs/**/*.mdx` 会触发 Turbopack/MDX 报错：`Expected process result to be a module, but it was ignored`。
- 之前把 MDX 机械转换为 TSX 只解决了报错，没有完成内容重构，不满足本次目标。

## 目标读者

目标读者是普通创作用户，已获得平台访问权限，想快速完成内容创作。用户关心：

- 平台有哪些创作入口。
- 图片、视频、画布、专项工作室分别适合什么场景。
- 如何提交任务、等待结果、查看历史、下载或复用。
- 如何把图片继续变成视频，或从故事/脚本推进到成片。

## 信息架构

### 开始创作

#### `/docs`

创作手册首页。作为总览页面，说明当前平台的主入口：

- 灵感首页：发现示例、从推荐内容开始创作。
- 创作：AI 生图、AI 视频。
- Toby Studio：音乐、短剧、绘本等专项模块。
- 灵动画布：自由编排节点、串联素材和生成步骤。
- 资产库：查看、下载、复用生成结果。

页面不再叫“平台简介”，不再强调旧工作台、积分统计、团队管理。

#### `/docs/user-guide`

快速上手。用一条完整路径讲清楚：

```text
登录 / 进入首页
  ↓
选择 AI 生图、AI 视频、灵动画布或 Toby Studio
  ↓
填写提示词 / 上传参考素材
  ↓
提交生成任务
  ↓
在历史或资产库中查看结果
  ↓
下载、复用或继续二次创作
```

### 核心创作

#### `/docs/image-generation`

AI 生图手册。覆盖：

- 从首页 AI 生图卡片或侧边栏“创作”进入。
- 文生图、参考图生图。
- 提示词输入、参考图上传、比例、质量、数量。
- 提交任务、查看历史、下载与复用。
- 写提示词建议：主体、风格、构图、光线、用途。

#### `/docs/video-generation`

AI 视频手册。覆盖：

- 从首页 AI 视频卡片或侧边栏“创作”进入。
- 首尾帧、参考生视频、纯文字视频描述。
- 分辨率、比例、动作描述、镜头运动。
- 视频任务耗时更长，提交后可离开页面。
- 完成后从历史或资产库预览、下载、复用。

#### `/docs/canvas`

灵动画布手册。覆盖：

- 从首页“灵动画布”或侧边栏“画布”进入。
- 三个入口：制作视频、生成图片、自由创作。
- 节点式创作思路：素材、文本、图片生成、视频生成、音频、拼接。
- 适合复杂链路、保留上下游关系、探索不同版本。

#### `/docs/assets`

资产库与历史复用。覆盖：

- 图片 / 视频资产切换。
- 日期筛选、缩略图浏览、详情查看。
- 下载、复用、删除、回收站。
- 说明“资产库”和“历史详情”的关系：结果完成后会沉淀为可复用资产。

#### `/docs/ai-assistant`

Toby.AI 创作助手。覆盖：

- 右下角悬浮入口。
- 对话助手：提示词优化、创意策划、文案改写、翻译。
- 图片解析：上传图片，提取画面信息和可复用提示词。
- 使用边界：助手生成内容需用户确认后再用于创作。

### 专项工作室

#### `/docs/toby-studio`

Toby Studio 总览。覆盖：

- AI 音乐：生成歌曲、纯音乐，管理音乐作品与克隆音色。
- AI 短剧：短剧脚本、分镜、成片工作流。
- AI 绘本：绘本故事、角色设定、连续画面生成。
- AI 海报、AI PPT：页面显示为待开放，只写入口状态，不写不存在的步骤。

#### `/docs/music`

AI 音乐。覆盖：

- 创建音乐作品。
- 搜索和浏览我的音乐作品。
- 音色克隆入口与生成状态。
- 生成完成后进入详情播放和查看歌词。

#### `/docs/short-drama`

AI 短剧。覆盖：

- 创建短剧项目。
- 从故事、分集、剧本、分镜逐步推进。
- 生成过程中保存项目，后续可继续编辑。
- 只写当前代码能确认的入口和流程，不虚构未确认按钮文案。

#### `/docs/picture-book`

AI 绘本。覆盖：

- 创建绘本项目。
- 故事、角色设定、连续画面生成的创作方向。
- 项目列表与继续编辑。
- 只写当前代码能确认的入口和流程，不虚构未确认按钮文案。

## 导航设计

`apps/web/src/app/docs/layout.tsx` 的侧边栏重组为：

```text
开始创作
- 创作手册首页
- 快速上手

核心创作
- AI 生图
- AI 视频
- 灵动画布
- 资产库与历史复用
- Toby.AI 创作助手

专项工作室
- Toby Studio 总览
- AI 音乐
- AI 短剧
- AI 绘本
```

删除旧导航里的“登录与账户”“工作台”“海报制作”“宣传短片”作为主入口。旧 URL 可按需保留兼容跳转，但不再作为手册主线。

不单独设置“创作工作流”导航组。图片转视频、故事到成片、资产复用等建议只作为相关页面内的使用提示出现，不创建独立工作流页面。

## 技术实现

为避免当前 `docs/**/*.mdx` 的 Turbopack/MDX 报错，所有 docs 页面使用 `page.tsx` 实现。

推荐新增共享文档组件：

- `apps/web/src/components/docs/docs-page.tsx`
  - 提供页面标题、说明、章节、步骤、提示块、图片展示、表格等组件。
- `apps/web/src/components/docs/docs-data.ts`
  - 存放文档导航与页面元信息，避免 layout 和页面各自维护文案。

页面内容可以直接写 TSX，不再把旧 Markdown 作为字符串渲染。这样便于插入截图、提示块和任务流，同时避免再次出现“只是搬旧文档”的问题。

## 图片与截图策略

不复用旧截图作为主要说明图。使用当前可访问页面重新截图并保存到 `apps/web/public/docs-images`。

截图原则：

- 能打开的页面使用真实页面截图。
- 页面因本地 dev server 缓存或模块解析问题打不开时，不伪造截图。
- 无法打开的功能页可使用当前首页入口图、侧边栏入口图或文字流程图替代，并在文案中避免说成“页面截图”。
- 截图命名按页面语义，例如 `docs-home-overview.png`、`docs-toby-studio.png`、`docs-assets-grid.png`。

## 验证方式

实施后进行以下验证：

1. 所有 docs 主路由返回 200。
2. 响应中不包含 `Expected process result` 或 `Server Error`。
3. `/login` 中的 `《AIGC 用户使用手册》` 仍能跳转到新快速上手页。
4. 所有 docs 页面引用的图片文件存在。
5. 不执行前端 build，不启动或重启 `localhost:6006`。

## 非目标

- 不写团队管理、用户管理、权限、设置、充值、后台管理教程。
- 不修复整个项目的 Turbopack/MDX 根因；本次通过 TSX 文档页面规避。
- 不虚构尚未开放的 AI 海报、AI PPT 具体操作步骤。
- 不改创作业务逻辑、生成接口、资产接口或认证流程。
