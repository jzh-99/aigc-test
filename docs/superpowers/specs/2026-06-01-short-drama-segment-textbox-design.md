# AI 短剧片段文本框结构升级设计

## 背景

当前 AI 短剧单集编辑页已经采用稳定的三栏布局：

- 左侧：素材库。
- 中间：当前片段编辑区。
- 中间底部：片段序列轮播。
- 右侧：预览与导出。

当前“片段”已经是视频生成按钮、片段轮播、预览导出统计中的核心单位。用户希望保留现有页面排版，只升级当前片段文本框里的内容表达，使一个片段可以包含“场景设定 + 多个分镜”，并继续通过 `@角色`、`@背景` 引用资产。

## 目标

- 保留现有单集编辑页整体排版。
- 保留左侧素材库、右侧预览导出、底部片段轮播。
- 保持片段是视频生成最小单位。
- 每个片段文本框展示并编辑：
  - 本片段场景设定。
  - 多个分镜描述。
- 分镜数量根据剧情节奏自动划分，不设置固定数量。
- 每个分镜时长可以手动选择并修改，范围为 `1-10` 秒。
- 视频生成时使用整个片段文本框内容作为片段 prompt。
- `@` 引用继续从当前文本框内容中提取，并作为片段视频生成的参考图。
- AI 生成片段脚本时，输出更接近参考图的结构化文本格式。
- 旧脏数据不做运行时兼容，按清理/重生成处理。

## 非目标

本次不做以下内容：

- 不重做单集编辑页三栏布局。
- 不移除底部片段序列轮播。
- 不新增剧集编排器。
- 不让分镜成为视频生成单位。
- 不给分镜增加独立的 `videoUrl`、`status` 或生成按钮。
- 不做片段级复杂时间线剪辑。
- 不在运行时兼容旧的脏片段结构。
- 不修改数据库表结构。

## 核心概念

### 片段

片段是视频生成的最小单位。

片段对应当前页面中的：

- 片段标题。
- 片段文本框。
- 片段时长。
- 片段 `@` 引用。
- 片段视频生成状态。
- 片段视频预览。
- 底部片段轮播卡片。

生成视频时，一次提交一个片段。

### 分镜

分镜是片段文本框中的结构化文本内容。

分镜只描述镜头，不单独生成视频。它可以包含：

- 分镜编号。
- 分镜时长。
- 景别。
- 机位或运镜。
- 画面动作。
- 对白或字幕。
- 需要出现的 `@角色` 或 `@背景`。

分镜数量不固定，由剧情复杂度、动作变化、对白节奏和镜头表达需要共同决定。简单片段可以只有少量分镜，复杂片段可以拆成更多分镜。

每个分镜时长支持用户手动修改，允许值为 `1-10` 秒。片段总时长由片段内所有分镜时长累加得到，并同步到片段的 `durationSeconds`。

## 文本框展示格式

片段文本框建议使用以下自然语言格式：

```text
本片段场景设定在：@十七年前的教室、@县城老中学的旧教室，白天，写实自然光。生成一个由以下 3 个分镜组成的视频。

分镜1 · 4s：远景，固定机位，平视拍摄空无一人的旧教室。阳光穿过布满灰尘的窗户斜射进来，旧桌椅凌乱，墙面斑驳。

分镜2 · 5s：中景，俯视机位，拍摄 @林微 在旧教室内整理旧物。她穿着素雅衬衫，动作安静专注。

分镜3 · 6s：近景，平视机位，拍摄 @林微 听到手机对话后的表情。她拿起手机，语气平静地拒绝见面，然后挂断电话。
```

该格式要求：

- 第一段必须描述本片段场景设定。
- 后续分镜必须按顺序编号。
- 每个分镜必须包含时长，时长范围为 `1-10` 秒。
- 出现角色或背景时使用 `@素材名`。
- 不引用不存在的素材名。
- 文本框仍然允许用户手动编辑。

## 数据模型

本次保守改动数据模型，不新增分镜数组作为运行时核心结构。

现有 `ShortDramaSegment` 继续作为视频生成单位使用：

```ts
interface ShortDramaSegment {
  id: string
  order: number
  title: string
  prompt: string
  mentionRefs: ShortDramaMentionRef[]
  durationSeconds: number
  videoUrl: string | null
  status: ShortDramaGenerationStatus
}
```

其中：

- `prompt` 保存完整片段文本，包括场景设定和多个分镜。
- `durationSeconds` 保存片段总时长，由片段内所有分镜时长累加得到。
- `mentionRefs` 从完整 `prompt` 中提取。
- `videoUrl` 是整个片段生成后的视频地址。
- `status` 是整个片段的视频生成状态。

不新增 `Shot.videoUrl` 或 `Shot.status`。

## AI 生成规则

后端生成单集片段脚本时，仍然生成 `episode.segments`。

每个 segment 要求包含：

- `title`：片段标题。
- `prompt`：完整片段文本，包含场景设定和多个分镜。
- `mentionNames`：该片段实际引用的素材名称。
- `durationSeconds`：片段总时长。

AI 提示词需要明确：

- 每个片段的分镜数量根据剧情自动划分，不固定数量。
- 每个分镜必须给出 `1-10` 秒范围内的时长。
- 分镜只写入当前片段 `prompt`。
- 片段才是视频生成单位。
- `durationSeconds` 是片段总时长，等于片段内所有分镜时长之和。
- 出现素材时必须使用 `@素材名`。
- `mentionNames` 只能从可用素材列表中选择。
- 不要虚构素材名称。

## 视频生成规则

用户点击“生成视频”时，仍然调用当前片段的视频生成接口。

生成输入：

- 当前 segment 的完整 `prompt`。
- 当前 segment 的 `mentionRefs` 对应图片。
- 当前 segment 的 `durationSeconds`。
- 项目画面比例。

视频生成结果写回：

- 当前 segment 的 `videoUrl`。
- 当前 segment 的 `status`。

分镜不产生独立任务。

## 前端交互

### 保留内容

以下 UI 保持现状：

- 顶部返回和集标题。
- 左侧素材库。
- 中间片段卡片布局。
- 当前片段标题。
- 前移、后移、删除按钮。
- 文本框下方 `@` 引用提示。
- 生成视频按钮。
- 底部片段序列轮播。
- 右侧预览与导出。
- 批量生成视频。

### 调整内容

只调整片段文本框中的默认内容和生成内容：

- 新增片段时，默认 prompt 可为空或带结构化占位文案。
- AI 自动生成片段时，prompt 使用“场景设定 + 分镜列表”格式。
- 用户手动编辑 prompt 后，继续自动提取 `@` 引用。
- 用户可以修改每个分镜的时长，时长选择范围为 `1-10` 秒。
- 分镜时长变化后，片段总时长随之更新，并作为片段视频生成时长。
- 当用户修改已生成视频的片段 prompt 时，应提示该片段需要重新生成；是否清空旧 `videoUrl` 由实现阶段结合现有交互决定。

## 脏数据处理

不做运行时旧结构兼容。

实现前需要清理已有脏数据，推荐处理方式：

- 对开发/测试环境中的旧短剧项目，清空旧 `episode.segments`。
- 让用户重新生成单集片段脚本。
- 或直接删除测试项目后重新创建。

代码中不添加“旧结构自动映射新结构”的兜底逻辑。
