# AGENTS.md 常见问题与解决方案 SOP —— 设计文档

> 目的：把"项目中反复出现的技术/环境/第三方问题"从零散经验升级为 AGENTS.md 里强约束的工作流程规则，并以四段式（现象→原因→解法→验证）沉淀已知高频问题，减少同类返工。

## 一、背景与问题

当前项目存在两类"反复掉同一个坑"的情况，但缺少系统化的沉淀机制：

1. **散落注意事项**：`AGENTS.md` 已有 PG OOM、Sharp 跨平台等说明，但夹在 Docker 部署章节里，不是"问题→原因→解法"的排查格式，遇到问题时不易被检索到。
2. **缺失沉淀规则**：`CLAUDE.md` 末尾（244-247 行）已有"同类问题重复出现就固化进本文件""流程反复出现就升级为 skill"的规则，但当前 git 主改文件 `AGENTS.md` 完全没有这条规则，两份本应同步的文档已经分歧。
3. **业管 A 豆迁移反复返工**：最近 30+ 条 commit 显示「本地积分 vs 业管 A 豆」迁移中，"A 豆余额落本地""fire-and-forget 调用业管""新增 toby_ 前缀"等已被多次纠正，但只存在于 handoff 文档里，未进入 AGENTS.md 强约束层。

### 覆盖盲区（本次重点修正）

调研发现项目同时存在 **3 个 Agent 指令文件**，分属不同工具，互不读取：

| 文件 | 谁会自动读 | 现状 |
|------|-----------|------|
| `AGENTS.md` | Codex / Cursor / 通用 Agent | 项目约定，事实上的通用入口 |
| `CLAUDE.md`（根目录） | 仅 Claude Code | 与 AGENTS.md 高度重复但有分歧 |
| `.claude/CLAUDE.md` | 仅 Claude Code | **工具层配置**（CodeGraph MCP、Playwright 登录），非项目约定 |

**问题**：
- 常见问题只写在 AGENTS.md 里 → 用 Claude Code 的同事（不读 AGENTS.md）看不到。
- 项目无 `GEMINI.md` / `.github/copilot-instructions.md` / `.cursorrules` 等 → Gemini CLI、Copilot、Windsurf 等工具**完全无入口**。
- `AGENTS.md:6` 和 `CLAUDE.md:6` 写着「加载全局规则 `~/.claude/CLAUDE.md`」，但该文件是**用户私有全局文件，换电脑/换同事就不存在**，等同于空指向。

**结论**：必须采用「AGENTS.md 为唯一权威源 + 其余入口只引导」策略，才能真正实现"任何同事、任何环境、任何 Agent 都能读到"。

### 实施期发现：CLAUDE.md 被 .gitignore 忽略（关键约束）

实施 Task 3 时发现：`.gitignore` 第 85-86 行明确忽略 `CLAUDE.md` 与 `**/CLAUDE.md`，且根目录 `CLAUDE.md` **从未进入版本库**（`git ls-files --error-unmatch` 报未跟踪）。

**这意味着**：
- 根目录 `CLAUDE.md` 是**本地私有文件**，同事 clone 仓库后看不到它。
- 因此 CLAUDE.md **不能作为团队入口**，它对"任何同事都能读到"这个目标无贡献。
- 真正的团队入口**只有 `AGENTS.md`**（进版本库，所有 Agent 工具通用）。

**经与用户确认的决策：保持现状**（CLAUDE.md 故意不入库，各人本地不同）。据此调整方案：
- `AGENTS.md` 仍是唯一权威源 + 唯一团队入口（Task 1、2 已完成，已入库）。
- 本地 `CLAUDE.md` 仍按"降级为引导文件"改写（让本机 Claude Code 指向 AGENTS.md），但**这只是本地修改，不 commit、不算团队交付物**。
- 把"`CLAUDE.md` 被 gitignore、不能作为团队入口"作为第 5 个常见问题沉淀进 AGENTS.md「常见问题与解决方案」章节，避免后续再踩。

## 二、范围

**纳入（本次要沉淀的问题类型）：**
- 技术性报错 / bug 根因与修复
- 环境 / 配置 / 部署问题
- 第三方集成踩坑（火山、TOS、Redis、PG、Kysely、业管平台等）

**不纳入：**
- 业务逻辑理解问题（计费规则、状态流转等）—— 这类走业务说明文档（如 `A豆积分体系说明.md`），不进排查章节。

## 三、方案

### 3.1 信息源策略：AGENTS.md 为唯一权威源

**核心原则**：项目约定、工作流程、常见问题**只写一份**，放在 `AGENTS.md`。其余所有 Agent 入口文件只做一句话引导，不重复内容，避免多份同步维护导致分歧（这正是当前 CLAUDE.md/AGENTS.md 分歧的根因）。

各文件分工如下：

| 文件 | 角色 | 本次处理 |
|------|------|---------|
| `AGENTS.md` | **唯一权威源 + 唯一团队入口**（进版本库）：项目概述、工作流程、规则、常见问题全在这里 | 新增「问题沉淀规则」+「常见问题与解决方案」章节（已完成并入库） |
| `CLAUDE.md`（根目录） | 本地私有文件（被 `.gitignore` 忽略，不入库），仅对本机 Claude Code 生效 | 按引导文件改写（指向 AGENTS.md），但**本地修改、不 commit**；不能作为团队入口 |
| `.claude/CLAUDE.md` | Claude Code 工具层配置（CodeGraph、Playwright） | **不动**（与本设计无关，是 MCP/浏览器工具配置） |

### 3.2 在 AGENTS.md 新增工作流程规则

在 `## 工作流程（非常重要）` 章节下追加一条流程级强约束（不是散落注意事项）：

> **问题沉淀规则**：同一个技术/环境/第三方集成问题，在本项目内出现第 2 次时，必须把解决办法按四段式（问题现象→根本原因→解决办法→验证方式）写入本文件「常见问题与解决方案」章节。业务逻辑理解问题不进此章节。

### 3.3 处理失效的全局引用

`AGENTS.md:6` 和 `CLAUDE.md:6` 现有「加载全局规则 `~/.claude/CLAUDE.md`」是空指向（用户私有全局文件，换环境即失效）。本次将其改为指向项目内权威源：

> 首先需要加载项目内的约定文件 `AGENTS.md`（本项目所有约定、规则、常见问题以 AGENTS.md 为准）。

### 3.4 新建「常见问题与解决方案」章节

在 AGENTS.md 中新增独立章节 `## 常见问题与解决方案`，置于「## 注意事项」之后、「## Docker 部署」之前。

每个问题用四段式记录：

```
### N. <问题标题>

- **问题现象**：报错信息 / 可观察症状 / 出现场景
- **根本原因**：为什么会发生，根因而非表象
- **解决办法**：关键命令 / 配置值 / 代码改动方向，不含大段代码
- **验证方式**：如何确认问题已解决
```

## 五、四段式写作规范（供后续沉淀参考）

- **问题现象**：写可被搜索到的报错关键字或可观察症状，例如错误码 `53200`、报错文案片段。便于下次遇到同类问题时能搜到。
- **根本原因**：写"为什么"，不是"是什么"。例如"PG 默认 work_mem 太小，流水表大查询触发 OOM"，而非"PG 报错了"。
- **解决办法**：给关键命令或配置取值，但不贴大段代码。读者看完知道该改哪里、改成什么。
- **验证方式**：给一个可执行的确认手段，例如 `docker logs`、某个 SQL、重启后观察指标。
- 整条控制在 8-15 行内，避免冗长。

## 六、不做什么（YAGNI）

- 不新建独立 troubleshooting 文件（按用户选择，沉淀在 AGENTS.md 内）。
- 不按模块拆分多个文件。
- 不盘点业务逻辑理解问题。
- 不重写 Docker 部署章节，只在排查章节补四段式闭环。
